# Подсистема ML

Лабораторный результат v0.4.7.2 хранит только отчёты и отпечатки нового предложения. Модельные бинарники остаются в `runtime` и не коммитятся. Предложение допущено только к новой слепой проверке v0.4.7.3; регистрация и автоматическое продвижение отсутствуют.

## Анализ v0.4.7.1

Каталог `ml/reports/v0_4_7_1/` содержит диагностический разбор замороженных прогнозов v0.4.7. Он не переобучает модель и не использует раскрытый набор для приёмки. Автономная проверка: `python -m tools.lab_console.verify_v0471`.

## Назначение

Признаки, артефакты кандидатов, политики оценки и решений, эксперименты,
протоколы и отчёты.

## Статус

`current` для действующего кандидата и контрактов среды выполнения; `historical/frozen`
для завершённых этапов.

## Место в архитектуре

Формирует модель решений основной линии. `v0.4.x` использует её результаты, но
не меняет модель.

## Основные каталоги

`features/`, `training/`, `decision/`, `analysis/`, `artifacts/`, `experiments/`,
`protocols/`, `reports/`, `tests/`.

## Разрешённые входы

Версионированные строки признаков и наборы данных, разрешённые зафиксированным
протоколом.

## Выходы

Артефакты кандидата, прогнозы, политики, манифесты и подтверждающие отчёты.

## Границы и запреты

Запрещены скрытое переобучение, адаптация по отложенной контрольной выборке и
изменение зафиксированных отчётов.

## Безопасный запуск и тестирование

```powershell
python -m pytest ml/tests -q
```

## Источники истины

Действующий кандидат `v03154:65a3dd912d845bc1`,
`ml/artifacts/v0_3_15_4/candidate_manifest.json`, [указатель протоколов](protocols/index.md) и
[указатель отчётов](reports/index.md).

Его целостность и зафиксированные метрики воспроизводимы, однако проверенная область ограничена одним синтетическим семейством генерации. Семантически независимая контрольная выборка, внешняя валидность и промышленная готовность не подтверждены; см. [переоценку v0.3.15.4–v0.3.15.5](../docs/experiments/v0_3_15_4_v0_3_15_5_methodology_reassessment.md).

Для будущей независимой проверки добавлен адаптер существующего 51-признакового
контракта. Он хранит отдельное причинное состояние каждой session, проверяет точный
порядок числовых полей и не допускает metadata в модель input. Новые обучающие или
оценочные данные при этом не создавались, артефакт кандидата не изменялся.

## Лабораторное обучение v0.4.6

Этап v0.4.6 использует только проверенные синтетические строки признаков и один зафиксированный рецепт из перечня разрешённых значений. Два независимых выполнения подтверждают воспроизводимость до формирования предложения кандидата. Новый двоичный файл модели хранится исключительно в среде выполнения и требует отдельного лицензионного решения; действующий реестр кандидатов не меняется.

## Слепая проверка v0.4.7

Новый независимый синтетический контрольный набор, эталонные метки и пакеты прогнозов существуют только в среде выполнения. В репозиторий входят агрегированные показатели, контрольные суммы предварительной фиксации, результаты обязательных проверок и ручное решение. Процедура выполнена корректно, однако предложение кандидата получило решение `failed_validation`; действующий кандидат и реестр не изменены.

## Новая слепая проверка v0.4.7.3

Новый набор v0473 не пересекается с v0.4.7 и v0.4.7.2. Разметка и строки прогнозов остаются только в среде выполнения; в Git входят только агрегаты, предварительные фиксации и доказательства порядка раскрытия. Предложение улучшилось, но не все обязательные критерии действующего кандидата пройдены, поэтому сохранён `failed_validation` и разрешён только v0.4.7.4.
