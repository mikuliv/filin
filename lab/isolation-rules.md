# Правила изоляции лабораторной сети

Лабораторный стенд Филин используется только в изолированной среде. Все сценарии должны быть безопасными, воспроизводимыми и ограниченными внутренними сервисами.

## Запрет внешних целей

Внешние адреса, публичные домены и сторонние сервисы запрещены для всех сценариев. В каждом сценарии атак должно быть указано:

- `external_network_allowed: false`;
- `allowed_targets`;
- `max_rate`;
- `max_duration_seconds`.

Если сценарий не содержит этих ограничений, он не должен запускаться даже в dry-run.

## Перечень разрешённых значений внутренних целей

Базовый Перечень разрешённых значений v0.1:

- `target-web`;
- `target-api`;
- `control-api`;
- `internal-dns`.

Расширение Перечень разрешённых значений допускается только после обновления документации стенда, сценариев и проверки маршрутизации сетей Docker.

## Лимиты интенсивности

Обычные сценарии должны иметь низкую или среднюю интенсивность. сценарии атак должны иметь низкую интенсивность и короткую длительность.

Рекомендуемые лимиты:

- сканирование портов: не более `10/min`, не дольше 120 секунд;
- ошибки авторизации: не более `6/min`, не дольше 180 секунд;
- web-probe: не более `8/min`, не дольше 150 секунд;
- низкоинтенсивный всплеск трафика: не более `15/min`, не дольше 90 секунд;
- симуляция маячкового обмена: не более `2/min`, не дольше 600 секунд.

Низкоинтенсивный всплеск трафика не является настоящей атакой DoS. Это контролируемый лабораторный сценарий для проверки реакции сенсоров и признаков на краткий рост числа запросов.

## Хранение логов и PCAP

Сырые логи, PCAP, JSONL и CSV не хранятся в Git. Они сохраняются локально в `lab/output/`, `datasets/raw/` или `datasets/processed/`.

Перед передачей датасета нужно проверить:

- отсутствие секретов и учетных данных;
- отсутствие внешних адресов;
- корректность временных окон;
- соответствие событий разметке манифеста;
- описание известных ограничений прогона.

## Правила выполнения v0.1

Активное выполнение сценариев разрешено только внутри сети Docker стенда. Исполнитель сценариев проверяет роли целей и использует только внутренний Перечень разрешённых значений:

- `target-web`;
- `target-api`;
- `control-api`.

`port_scan` выполняется как ограниченная TCP проверка соединения только разрешенных внутренних портов. `low_rate_dos` является низкоинтенсивной имитацией всплеска запросов HTTP и не должен использоваться как настоящая атака DoS.

Для проверки pipeline без сетевой активности используется `--mock`. В этом режиме создаются только события выполнения, а сетевые обращения не выполняются.

В расширенном режиме имитации также создается `traffic_events.jsonl` с синтетическими учебными событиями. Эти события нужны для проверки нормализации, отчета и будущего построения признаков, но не заменяют реальный сбор трафика на стенде.
