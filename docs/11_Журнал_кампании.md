# Журнал кампании

Журнал кампании — дописываемая последовательность событий, которая позволяет восстановить ход исполнения. В нём фиксируются начало единицы, начало и завершение попытки, результаты проверок, ошибки, повторные попытки, фиксация каталога и окончание сеанса.

Каждая запись сериализуется канонически и связывается с предыдущей контрольной суммой той же цепочки. Начальное значение задаётся протоколом; изменение поля или удаление записи нарушает цепочку. Журнал не переписывается при исправлении документации и не используется для подмены исторического результата.

Долговечная запись отделена от диагностического trace. Для отправки событий сначала выполняется `fsync`/commit, затем строгий ACK, после чего разрешаются checkpoint и compaction. Нулевой backlog без совпадения source, connector и receiver недостаточен: проверяется полный набор идентификаторов и канонических байтов.

Название файла `campaign-ledger.jsonl` сохраняется как идентификатор; в русском тексте используется термин «журнал кампании».
