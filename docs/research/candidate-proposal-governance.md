# Управление предложениями лабораторных кандидатов

`proposal_id` и `candidate_id` принадлежат разным пространствам идентичности. Предложение v0.4.6 существует только в локальном каталоге предложений кандидатов и не может быть зарегистрировано, активировано, продвинуто или автоматически выбрано.

Допустимый жизненный цикл: `draft` → проверка происхождения и утечек → воспроизводимое обучение → зафиксированное предложение кандидата → предварительная внутренняя проверка → сравнение с действующим кандидатом → заранее объявленные обязательные критерии допуска → сохраняемое ручное рассмотрение → `admitted_to_separate_validation` либо `rejected`.

Допуск означает только право подготовить отдельный будущий протокол. Реестр кандидатов, активный артефакт, серверная часть и зафиксированные подтверждающие материалы предыдущих этапов остаются неизменными. API намеренно не содержит операций загрузки, произвольных команд, регистрации, активации, продвижения или замены активного кандидата.
