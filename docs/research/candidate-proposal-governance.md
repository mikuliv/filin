# Управление предложениями лабораторных кандидатов

`proposal_id` и `candidate_id` принадлежат разным пространствам идентичности. Предложение v0.4.6 существует только в локальном предложение кандидата catalog и не может быть зарегистрировано, активировано, продвинуто или автоматически выбрано.

Допустимый жизненный цикл: `draft` → проверка происхождения и leakage → реальные воспроизводимые обучения → Зафиксировано предложение кандидата → предварительная внутренняя проверка → сравнение с действующим кандидатом → заранее объявленный обязательные критерии допуска → сохраняемое ручное рассмотрение → `admitted_to_separate_validation` либо `rejected`.

Admission означает только право подготовить отдельный будущий протокол. реестр кандидатов, active артефакт, серверная часть и Зафиксировано подтверждающие материалы предыдущих этапов остаются неизменными. API намеренно не содержит upload, arbitrary command, register, activate, promote или replace-active операций.
