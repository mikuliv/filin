# Причинно упорядоченные признаки

«Причинный» здесь означает только порядок вычисления и запрет заглядывать в будущее. Значение строится из наблюдаемых строк текущего окна и явно разрешённого состояния предыдущих окон; оно не доказывает причину события.

## Почему признаки считаются сетевыми

Источник каждого признака — наблюдение сетевого обмена или детерминированная сводка журналов `conn.log`, `http.log` и `dns.log`. В контракте закреплены 51 поле, относящееся к потокам, пакетам, направлениям, HTTP-методам и ответам, DNS-наблюдениям, интенсивности, интервалам, устойчивости и разнообразию. Это описание происхождения признаков, а не утверждение о причинном эффекте.

## Порядок

Сначала извлекаются базовые rates и shares из `conn.log`, `http.log` и `dns.log`. Затем рассчитываются изменения, скользящие сводки, робастные отклонения и временная устойчивость. В конце добавляются контекстные признаки ответа, восстановления, разнообразия методов и баланса направления. Контракт сохраняет этот порядок ровно для 51 поля. Вектор строится только после временного исключения разрешённых потоков с marker из копии журналов.

## Ограничения и исключения

| Группа | Примеры | Ограничение интерпретации |
|---|---|---|
| Частоты и доли | `flows_per_second`, `tcp_flow_share` | Описывают наблюдённый обмен |
| Объём и направление | `bytes_per_flow`, `response_bytes_share` | Не содержат полезную нагрузку |
| Изменения во времени | `delta_flows_per_second`, `rolling_activity_slope` | Используют только разрешённую историю окон |
| Регулярность | `request_spacing_cv`, `periodicity_stability` | Не доказывает вредоносность |
| Восстановление | `success_response_share`, `retry_recovery_rate` | Формулы контракта не доказывают причинный эффект |

Удаление маркерного обмена выполняется перед вычислением признаков:

1. Сохранить исходные журналы и их контрольные суммы.
2. В рабочей копии выделить HTTP-строки с префиксом `/sensor-marker/`.
3. Исключить эти строки и связанные UID из рабочей копии `conn.log`; DNS не фильтровать.
4. При пересечении UID маркера и сценария остановить обработку с `processing_integrity_failure`.
5. Рассчитать признаки по очищенным копиям и проверить точный порядок полей.

Extractor не использует label, профиль инфраструктуры, имя сценария, скрытое состояние генератора или будущие окна. При смене `run_id` состояние очищается. Нулевой знаменатель даёт безопасное конечное значение по формуле кода; неизвестное обязательное поле не угадывается.

В модельный вход не попадают `execution_token`, `scenario_token`, семейство генератора, профиль инфраструктуры, реализация цели, порт, фон, имя файла, путь, marker metadata и метка класса. Эти сведения нужны для контроля плана и аудита происхождения, но не должны служить скрытыми признаками. Исходные PCAP и исходные Zeek-журналы не изменяются; маркерные строки исключаются только из временной копии. Смешанный UID маркера и сценария приводит к `processing_integrity_failure`.

Полный перечень и источник каждой формулы: [построение 51 признака Phase 1](phase1-feature-construction.md). Оценка переносимости, а не название признака, должна показать, что модель не использует proxy генератора или инфраструктуры.
