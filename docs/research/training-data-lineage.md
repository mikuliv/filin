# Происхождение данных обучения

Каждая строка должна быть прослеживаема по цепочке `scenario → common client → target → sensor → PCAP → Zeek → SessionFeatureAdapter → 51 features`. Для каждой стадии фиксируются версия плана, единица выполнения, digest входов и результат проверки целостности. В модель не передаются label, marker metadata, `execution_token` или поля, раскрывающие семью генератора и профиль.

## Разбиения

Повтор `0` — `development_train`, повтор `1` — `development_calibration`, повтор `2` — `blind_internal_holdout`. Это первичное разбиение, задаваемое планом. Группировки по семейству, инфраструктуре и цели применяются только как аналитические представления; сессию нельзя разделить между наборами или вернуть из контрольной выборки в обучение.

## Границы и проверки происхождения

Сценарий задаёт намеренные параметры поведения, общий клиент формирует запросы, целевой сервис отвечает, а сенсор фиксирует сетевой обмен. PCAP является исходным наблюдением. Zeek извлекает структурированные сетевые журналы, после чего `SessionFeatureAdapter` строит строку в порядке, закреплённом контрактом 51 признака. Временная очистка потоков с marker не изменяет исходный PCAP и исходные журналы.

Идентичность строки связывается с `evaluation_token`, digest контракта признаков, digest порядка и манифестом целостности. `execution_token`, имя сценария, семейство генератора, профиль инфраструктуры, цель, порт, фон и служебные маркеры остаются данными происхождения и контроля, а не входами модели.

Сверяются digest контракта признаков, порядок полей, candidate identity, манифест строки, код исключения и журнал. Неразрешённый обязательный параметр не заполняется догадкой. Неполное происхождение блокирует критерий и продвижение.

## Будущая модель

Первичное разбиение задаётся только номером повтора: `0` — `development_train`, `1` — `development_calibration`, `2` — `blind_internal_holdout`. Аналитические представления по семейству, инфраструктуре и цели используются для отдельных проверок переносимости и не меняют `primary split`.

На текущем этапе модель ещё не обучалась. До будущего обучения должны быть зафиксированы состав строк, seed, конфигурация обучения, версия зависимостей, digest модели и порядок раскрытия меток. Поэтому этот документ описывает требования к будущему корпусу, а не уже полученный научный результат.
