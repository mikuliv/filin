# Единый стандарт документации

## Язык и терминология

Человекочитаемый текст пишется по-русски. Технические идентификаторы, пути, команды,
поля и названия стандартов сохраняются без изменений. При первом употреблении специальный
английский термин получает русское пояснение. Используйте [глоссарий](../reference/glossary.md).

## Заголовки

Один H1 на документ. Уровни не пропускаются. Названия описывают предмет, а не номер
задачи. Внутренние ссылки и якоря проверяются валидатором.

## Текущий и исторический материал

Текущий документ описывает только действующее состояние. Исторический результат не
удаляется, но получает явную отметку жизненного цикла и не используется как текущий путь выполнения.

## Авторитетность

`authoritative_for` используется только для уникальной доменной точки входа.
Машиночитаемые статус и политика всегда имеют приоритет над описательным текстом.

## Утверждения и подтверждающие материалы

Каждое утверждение о возможностях указывает этап, область применимости, подтверждающие материалы и ограничения.
Нельзя превращать лабораторный результат в утверждение о внешнем или промышленном применении.

## Ссылки и блоки кода

Используйте относительные ссылки внутри репозитория. Абсолютные локальные пути, секреты и
персональные данные запрещены. Команда должна существовать и указывать рабочий каталог и побочные эффекты.

## Диаграммы

Mermaid применяется только когда упрощает поток, границу доверия или жизненный цикл. Диаграмма
не должна создавать причинную семантику, отсутствующую в контракте.

## Служебный заголовок

Метаданные текущего документа хранятся в документационной описи. Видимый служебный заголовок YAML в начале текущей страницы не используется: это проверяет `validate_documentation_v2`. Запись описи содержит, в частности:

```yaml
doc_schema: filin_document_v2
title: Понятный заголовок
document_type: overview
audience:
  - developer
lifecycle_status: current
authoritative_for: []
source_of_truth:
  - path/to/source
last_reviewed_stage: <этап, подтверждённый источником>
generated: false
evidence_immutable: false
```

Защищённые файлы не меняются ради метаданных.

## Генерируемые документы

В описи указываются `generated: true`, пути источников, версия генератора и команда воспроизведения.
Если генератор поддерживает частичное обновление, его область ограничивается `<!-- generated:start -->` и `<!-- generated:end -->`.

## README подсистемы

Обязательны назначение, статус, место в архитектуре, файлы, входы, выходы,
границы, безопасный запуск, тестирование, источники истины и связанные документы.

## Перенаправление

Перенаправление содержит один H1, каноническую ссылку, причину,
отметку жизненного цикла и явное отсутствие авторитетности. Оно не повторяет прежние признаки возможностей.

## Документация этапа

Новый этап обновляет индексы протоколов и отчётов, реестр статуса, ограничения и
следующий этап только после результата политики. Защищённые отчёты задним числом не редактируются.

## Проверка

```powershell
python -m tools.docs.build_documentation_inventory
python -m tools.docs.validate_documentation_v2 --strict
```

При обновлении обеих описей сначала создайте индексы, затем языковую опись и последней — общую документационную опись. Последняя фиксирует контрольную сумму уже обновлённого языкового отчёта. Не отключайте проверку его контрольной суммы ради успешного результата.

Для нового документа также проверьте лицензионную область применимости: документация обычно
получает CC-BY-4.0 через `REUSE.toml`, а вставки сторонних схем, изображений и текста требуют
отдельного указания происхождения и исходной лицензии. Защищённые подтверждающие материалы нельзя
менять ради заголовка SPDX.
