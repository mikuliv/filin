# Зафиксированные подтверждающие материалы и лицензирование без изменения байтов

Защищённый набор строится существующим `tools.docs.documentation_v2.build_protected_set`. Этап не добавляет комментарии SPDX в такие файлы и не изменяет их байты. Лицензия назначается внешне через `REUSE.toml` и отражается в `frozen-spdx-mapping.json` с исходным SHA-256 и защищающими манифестами.

Это сохраняет научную воспроизводимость и одновременно делает назначение лицензии машиночитаемым.

Исходный `frozen-spdx-mapping.json` сохраняется как историческая таблица и задним числом не переписывается. Обнаруженные записи со смешанной основой вычисления SHA, расширение защищённого множества и санкционированные замены валидаторов оформляются отдельными файлами коррекции `frozen-spdx-mapping-correction-v1.json`, `frozen-spdx-mapping-correction-v2.json` и `frozen-spdx-mapping-correction-v3.json`. Коррекции перечисляют каждый путь явно, связывают прежнюю контрольную сумму с SHA канонического объекта Git и не разрешают универсальный резервный допуск по окончаниям строк.

Для пакета v0.3.15.3 файл `docs/audit/v0_3_15_3-digest-correction-v1.json` отдельно связывает 32 исторические CRLF-представления артефактов и CRLF-представление manifest с каноническими LF-байтами Git blob. Каждая запись фиксирует обе контрольные суммы, оба размера и commit происхождения. Валидатор применяет преобразование только для явно перечисленной записи и проверяет обе representation; это не изменяет научные артефакты и не разрешает произвольную нормализацию окончаний строк.

`licensing/repository-license-manifest.json` имеет другой жизненный цикл: это текущая изменяемая лицензионная опись репозитория. Она перестраивается для текущего состояния Git и не служит научной фиксацией.
