# Правила русскоязычной терминологии

## Основной принцип

Обычный повествовательный текст пишется на естественном русском языке. Точное техническое значение указывается после русского объяснения в обратных кавычках: действующий кандидат (`active_candidate`), решение «проверка не пройдена» (`failed_validation`).

Идентификатор не повторяется в каждом предложении. После первого пояснения используется русское название.

## Что не переводится

Без изменения сохраняются:

- имена файлов и каталогов;
- команды и параметры;
- адреса программного интерфейса;
- ключи Файлы JSON и YAML;
- значения программных перечислений;
- имена схем и контрактов;
- переменные окружения;
- контрольные суммы;
- официальные названия программ, библиотек, стандартов и форматов.

Такие элементы оформляются как код. Официальные тексты лицензий и неизменяемые подтверждающие материалы не редактируются.

## Предпочтительные соответствия

Точный идентификатор предложения кандидата (`proposal`) используется только при обращении к программным структурам.

| Точное английское понятие | Русское название |
|---|---|
| `active candidate` | действующий кандидат |
| `candidate registry` | реестр кандидатов |
| `proposal` | предложение кандидата |
| `prediction package` | пакет прогнозов |
| `label unlock` | раскрытие эталонной разметки |
| `control pack` | контрольный набор |
| `blind validation` | слепая проверка |
| `evidence bundle` | комплект подтверждающих материалов |
| `runtime-only` | только в среде выполнения |
| `backend integration` | подключение к серверной части |
| `acceptance gate` | обязательные критерии приёмки |
| `dry run` | пробный запуск без выполнения |
| `source of truth` | авторитетный источник |
| `holdout` | отложенная контрольная выборка |
| `test oracle` | тестовый эталон |

Полный машиночитаемый перечень находится в `docs/reference/russian-technical-terms.json`. Допустимые технические обозначения перечислены в `docs/reference/allowed-technical-identifiers.json`.

## Научная точность

Нельзя заменять гипотезу фактом, отношение причиной, лучшую поддержку истинностью, а технически успешную процедуру положительным научным решением. Для v0.4.7 обязательно сохраняются решение `failed_validation`, шесть неустранённых критических различий и запрет v0.4.8.
