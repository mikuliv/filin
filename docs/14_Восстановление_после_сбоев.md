# Восстановление после сбоев

Если запуск не начался, незавершённое намерение остаётся диагностическим и не превращается в научную запись. Если попытка началась, но оборвалась, состояние помечается неполным; автоматическое объявление успеха запрещено. После захвата может существовать PCAP без обработанных журналов — это промежуточный артефакт, а не завершённый сеанс.

После обработки могут существовать Zeek logs и строка признаков, но без оценки или записи сопоставления. После создания сопоставления всё ещё требуется зафиксировать каталог результатов и финальную запись журнала. Если финальная запись не успела сохраниться, восстановление сначала сверяет checkpoint, журнал, цепочку хэшей и содержимое каталога; при неоднозначности применяется fail-closed и сеанс блокируется для ручного разбора.

Checkpoint записывается атомарной заменой временного файла. При возобновлении используются только ранее подтверждённые элементы, повторная оценка уже зафиксированных данных не допускается. Отдельные каталоги каждого `run_id` предотвращают повторное подключение томов и нарушение независимости.
