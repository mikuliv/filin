# Сторонние зависимости и лицензии

> Таблица предназначена для технической инвентаризации. Версии контейнерных образов с меткой `latest`, транзитивные пакеты операционной системы и фактически загруженные манифесты образов требуют отдельного SBOM перед распространением. Указанная ниже совместимость не является юридическим заключением.

## Принцип использования

Большинство библиотек подключаются как зависимости среды выполнения или среды сборки; их исходный код не копируется в репозиторий Filin. При распространении контейнеров, пакетов Python, образов или кода поставщика обязательства могут отличаться от простого локального использования.

## Внешние образы и воспроизводимость

Для Zeek и Suricata закреплены метки версий, используемые защитной проверкой непрерывной интеграции, но ещё не закреплены контрольные суммы образов. Перед внешним распространением следует закрепить эти суммы, собрать SBOM и сохранить лицензионные уведомления для каждого образа и его базовых пакетов ОС.

Compose также объявляет `elastic/filebeat:8.15.0`, `elasticsearch:8.15.0` и `kibana:8.15.0`. Эти сервисы не образуют доказанной кодовой связи с историческим Anomalyzer, но их лицензирование нельзя описывать как Apache-2.0 без проверки конкретного дистрибутива. Elastic указывает ELv2 для стандартного дистрибутива Elasticsearch/Kibana и ограничения на предоставление продукта как управляемой службы. См. [частые вопросы Elastic](https://www.elastic.co/licensing/elastic-license/faq/).

## Исторические зависимости

`Anomalyzer-main/model-training/requirements.txt` дополнительно объявляет пакеты imbalanced-learn, matplotlib, seaborn, torch и ONNX. Они не становятся зависимостями Filin только потому, что находятся в соседнем историческом каталоге. Их нельзя переносить без отдельной инвентаризации и рассмотрения.

## Практические действия перед лицензированием/распространением

1. Зафиксировать версии Python в файле блокировки и контрольные суммы образов Docker.
2. Сформировать SBOM для образов Filin и дистрибутива среды выполнения.
3. Сохранить уведомления и лицензии сторонних компонентов, а также выполнить применимые обязательства по предложению исходного кода.
4. Решить, будет ли распространяться стек Compose с образами Suricata и Elastic или они останутся ссылками только для разработки.
5. Проверить условия Docker Desktop для организации: [официальные условия](https://docs.docker.com/subscription/desktop-license/).

## Актуальная машинная инвентаризация

Объявления зависимостей Python и состав разрешённого локального окружения находятся в `docs/licensing/python-dependencies-*.json`; контейнерные ссылки — в `docs/licensing/container-images.json`; объединённые уведомления — в `THIRD_PARTY_NOTICES.md`. Эти реестры создаются без сети и не заявляют включение пакетов или слоёв образов в распространяемые исходные материалы.
