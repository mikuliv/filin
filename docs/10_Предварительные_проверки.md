# Предварительные проверки

Есть два разных уровня проверки.

## Готовность кампании

Проверяется до начала всей кампании: доступен Docker Engine, присутствуют закреплённые образы, часы пригодны для протокола, подготовлены сети и каталоги, секрет существует вне Git, журнал имеет допустимое начальное состояние, а манифест и следующий идентификатор исполнения согласованы. Эта проверка не запускает научные сценарии и не загружает модель.

## Проверка перед сеансом

Перед каждым сеансом дополнительно проверяются свободный `run_id`, чистый каталог, отсутствие незавершённой попытки, корректный namespace, доступность целевого сервиса, возможность захвата, место на диске и отсутствие конфликтующего checkpoint. Только после успешного результата создаётся попытка.

Проверки работают по принципу fail-closed: неизвестное состояние означает запрет запуска. Успешная предварительная проверка не является научным результатом; она лишь разрешает перейти к следующему безопасному шагу.
