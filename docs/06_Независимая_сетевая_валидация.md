# Независимая сетевая валидация

Старая проверка строилась в основном на синтетических клиентских наблюдениях. В таком наборе генератор, профиль инфраструктуры или порт могли стать скрытым признаком класса. Это утечка по генератору: модель распознаёт происхождение данных вместо поведения. Инфраструктурная зависимость возникает, когда `profile → target → port` всегда совпадает и модель использует топологию как замену содержательной сетевой закономерности.

Новая проверка строится по фактическому трафику: два семейства генераторов (`family_a`, `family_b`), два инфраструктурных профиля (`profile_a`, `profile_b`), две целевые реализации и два порта комбинируются так, чтобы класс не был однозначно связан с одним фактором. Контрфактические пары меняют один фактор при сохранении поведения; провал такой пары указывает на зависимость от контекста.

Факторный план содержит 6 типов поведения × 2 семейства генераторов × 2 профиля × 2 реализации × 2 порта × 3 уровня интенсивности = 288 шаблонов. Три повторения дают 864 единицы исполнения. Фоновая активность распределяется сбалансированно внутри шаблонов и не является дополнительным множителем полного плана: иначе размер кампании перестал бы соответствовать заранее замороженному протоколу.

Повторение 0 используется для обучения, повторение 1 — для калибровки, повторение 2 — для внутренней отложенной проверки. Последнее не используется для настройки модели. Такой раздел сохраняет смысл независимой оценки, хотя весь стенд остаётся лабораторным и не заменяет внешний корпус.
