# Архитектура

## Слои системы

`lab` содержит Docker-стенд, сценарии, генераторы, кампании и сенсор. `collectors` отвечает за канонические события, очереди, контрольные суммы, повторные попытки и локальный приёмник. `ml` содержит протоколы, замороженные кандидаты, оценивание и аудиты. `backend` — отдельный прототип интеграции; он не подключён к текущему сенсору. `tools` содержит проверки и отчёты, а `docs` — описания, контракты и историю решений.

## Движение данных

```text
сетевой сценарий
→ traffic-client
→ внутренняя Docker-сеть
→ целевой сервис
→ sensor sidecar
→ PCAP
→ Zeek
→ нормализованные события
→ строка из 51 признака
→ замороженная оценка
→ состояние эпизода
→ пассивное событие
→ журнал/очередь/приёмник
```

Маркеры начала и конца проходят через сеть как реальные запросы, но исключаются из признаков. Метка сценария и служебные поля не должны попадать в путь построения признаков.

## Границы доверия

В v0.3.16 и последующих репетициях сенсор, connector и reference receiver размещаются в отдельных внутренних сетях. Порты наружу, `host network`, Docker socket и privileged-контейнеры запрещены. Контейнеры используют закреплённые локальные образы, ограниченные права и раздельные каталоги результатов.

## Контроль целостности

Протоколы, порядок признаков, кандидаты, манифесты и кампании фиксируются SHA-256. Сырые PCAP, журналы Zeek и результаты выполнения являются артефактами среды и не переписываются ради обновления текста документации.
