# Docker-инфраструктура

Лабораторный стенд использует `filin_lab_net` для клиентского трафика, `filin_monitor_net` для сенсоров и хранилища и `filin_mgmt_net` для управляющих компонентов. `traffic-client` обращается только к разрешённым внутренним именам. `target-web`, `target-api`, `control-api` и `target-ssh-sim` являются учебными сервисами; они не моделируют полноценную производственную сеть.

Сенсор не использует Docker socket, privileged mode или host network. Такой дизайн ограничивает область наблюдения и уменьшает риск изменения хоста. Образы закрепляются версиями, а научные этапы используют локальные образы без неявной загрузки из сети.

Проверка стенда выполняется с пояснением ожидаемого результата:

```bash
docker compose -f lab/docker/docker-compose.lab.yml up -d --build
docker compose -f lab/docker/docker-compose.lab.yml ps
```

Первая команда поднимает сервисы, вторая показывает их состояние. Ошибка запуска означает, что научный сеанс не разрешён; сначала проверяются образы, сети, права и оставшиеся контейнеры.
