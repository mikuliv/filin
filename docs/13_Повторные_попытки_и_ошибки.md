# Повторные попытки и ошибки

Правило числа попыток задаётся конкретным протоколом и не должно переноситься между версиями без проверки. В текущем runtime-контракте corrective v0.3.15.1 поле `maximum_attempts` равно 4; ранние научные планы могли ограничивать число попыток двумя. Поэтому документация не смешивает эти значения: для конкретной кампании приоритет имеет её frozen protocol.

Повтор разрешён только для классифицированных временных сбоев: `temporary_unavailable`, `connection_timeout`, `connection_reset`, `http_429_retry_after`, `http_503`, `slow_receiver`, а также для предусмотренных точек перезапуска. Некорректная схема, неизвестный ACK, ошибка сертификата, нарушение приватности, повреждение канонических байтов и конфликт идентичности являются окончательными отказами.

Повтор использует ограниченную экспоненциальную задержку с детерминированным jitter. Каждая попытка получает отдельную запись в журнале; повторная доставка не должна создавать второе смысловое событие. Не переводите reason codes: они являются машинными ключами, рядом следует давать русское объяснение.
