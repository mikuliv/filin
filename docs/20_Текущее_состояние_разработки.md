# Текущее состояние разработки

Авторитетный статус хранится в `docs/status/project-status.yaml`. Завершённый этап — v0.3.17; следующий разрешённый — corrective v0.3.17.1. Его задача: исправить historical-anchor audit, семантику clock/latency, performance gates, проверку повреждений пакета и воспроизводимость финализатора.

Разрешены: локальные unit/regression tests, read-only аудиты, подготовка документации и проектирование corrective этапа. Запрещены: v0.3.18, реальный shadow mode, backend integration, production, automatic enforcement, внешние сетевые соединения и изменение frozen scientific artifacts.

Главные ограничения:

- внешний корпус всё ещё нужен для оценки внешней обобщаемости;
- historical synthetic metrics не являются доказательством production validity;
- положительный transport result не отменяет отрицательный scientific policy;
- после начала кампании frozen protocol нельзя менять без новой revision, новых идентификаторов и новых контрольных сумм;
- reference receiver не является backend.

Исторические неудачи — отсутствие корректного PCAP, сброс `PATH` при `bash -lc`, неверный registry anchor, transport lag, общий каталог volumes и недостаточная corruption-проверка — являются частью доказательной истории и не скрываются.
