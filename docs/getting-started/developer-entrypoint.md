# Точка входа разработчика

Начинайте с границ системы и источников истины, а не с отдельного скрипта. Новое
поведение должно быть связано с контрактом, тестом и описанием допустимого этапа.

1. Прочитайте [границу между текущими и историческими компонентами](../architecture/current-vs-historical.md).
2. Подготовьте [локальное окружение](local-environment.md).
3. Найдите компонент в [каталоге](../reference/component-directory.md) и прочитайте его README.
4. Проверьте схемы входных и выходных данных через [индекс контрактов](../contracts/index.md).
5. Используйте [справочник команд](../reference/command-reference.md).
6. Запустите тесты компонента и documentation validators.
7. Не изменяйте protected files из [реестра](../audit/protected_documentation_v2.json); для пояснений создавайте отдельный документ со ссылкой на защищённый источник.

Изменение возможностей требует отдельной версии этапа, протокола и результата
политики. Один только документационный коммит не может разрешить новое поведение.
