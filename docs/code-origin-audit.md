# Технический аудит происхождения кода

## Методика

Сравнение выполнено между всеми файлами `Anomalyzer-main/` и `filin/`:

1. SHA-256 точного содержимого;
2. SHA-256 текста после удаления строковых комментариев и пробельных символов для `.py`, YAML, JSON, Markdown и текстовых файлов;
3. структурное попарочное сравнение нормализованных файлов Python (`SequenceMatcher`, порог 0.45);
4. `git log --follow`, `git log --diff-filter=R`, сведения об именах и состояниях файлов, история авторства и `git blame` ключевых файлов;
5. поиск импортов, ссылок на пути, команд выполнения, имён моделей и преобразователей, а также ссылок на ONNX и CICIDS.

## Пограничные места для дальнейшей проверки

- `ml/configs/inference.yaml` описывает локальные пути к ONNX и преобразователю. Это не ссылка на исторический артефакт, но перед распространением следует закрепить происхождение каждой подставленной модели.
- серверная часть, FastAPI, Docker Compose и шаблоны машинного обучения могут быть концептуально похожи на типовые решения; автоматическое сравнение не доказывает отсутствие заимствований идей или внешних источников вне истории Git.
- Автор Git у всех доступных коммитов один. Это не снимает риск служебного произведения, неучтённых участников или прав третьих лиц.

## Ограничения метода

Аудит не может обнаружить удалённую до Коммит историю, локальные непубликовавшиеся исходники, копирование с сильной ручной переработкой или правовой характер творческого сходства. Результат применим как техническое доказательство отсутствия обнаруженных текстовых и заимствований среды выполнения, а не как юридическая экспертиза.
