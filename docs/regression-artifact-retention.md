# Стандарт хранения артефактов регрессии

## Подтверждающие материалы теневого режима v0.3.14

В Git остаются контракт, политики, модуль экспорта, аудиты, тесты и документация. Канонические события, буфер, результаты повторного воспроизведения, трассировки и отчёты относятся только к среде выполнения и исключены из Git. Зафиксированные материалы v0.3.13 используются только для чтения.

## Артефакты v0.3.13

В Git хранятся протокол, политики, код, тесты и документация. PCAP, журналы Zeek, таблица признаков, хранилище меток, прогноз, метрики и комплект подтверждающих материалов остаются игнорируемыми артефактами среды выполнения; их хеши связаны манифестом и фиксациями.

v0.3.12.2 сохраняет в Git строгие манифесты трёх комплектов, а объёмные прогнозы, показатели, результаты бутстрепа и отчёты о производительности — только как воспроизводимые артефакты среды выполнения. Манифест отдельно фиксирует файловый хеш источника сопоставления эпизодов и канонический хеш самого зафиксированного сопоставления.

Каждое новое измерение после v0.3.12.1 закрывается только вместе с полным неизменяемым комплектом регрессии. Манифест должен быть создан до прогнозирования и содержать идентификатор этапа, SHA-256 протокола, кампании, исходного коммита и фиксации зависимостей.

Обязательны зафиксированная таблица с каноническими 51 признаками и их порядком, уникальные идентификаторы строк, отдельные сопоставления для запуска, причинного порядка и ключа активности, а также отдельные таблица меток и сопоставление эпизодов. Сопоставление эпизодов создаётся до прогнозирования; таблица меток не может быть входом модели при прогнозировании.

Комплект хранит манифест захвата, идентификатор исторического кандидата, манифест кандидата, неизменяемый прогноз, политику метрик и результат политики с версиями схем и SHA-256. Единственная копия в среде выполнения без отслеживаемого манифеста недопустима. PCAP или журналы Zeek, из которых теоретически можно повторно извлечь признаки, не заменяют исходную зафиксированную таблицу признаков.

Перед закрытием выполняется самопроверка совместимости: каноническая проекция 51 признака, уникальность и порядок строк, сопоставления запуска, причинного порядка и активности, отделение меток, сопоставление эпизодов и проверка готовности только по хешам без прогнозирования моделью. Неполный комплект получает `regression_bundle_complete: false` и не считается пригодным для научной проверки регрессии.

Проверка выполняется командой:

```powershell
python tools/audit/validate_regression_bundle.py --manifest <path> --strict
```

`--metadata-only` разрешает инвентаризацию временно недоступных файлов, но никогда не подтверждает полноту комплекта.

## Теневое испытание v0.3.15

В Git сохраняются протокол, политики, сводные научные отчёты и манифест комплекта. PCAP, журналы Zeek, таблицы признаков, хранилище меток, построчные прогнозы и события, записи получателя, буфер, контрольные точки и трассировки ресурсов остаются игнорируемыми артефактами среды выполнения. Их хеши фиксируются в отслеживаемом манифесте.
