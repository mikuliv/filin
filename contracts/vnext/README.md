# Контрактная основа Filin следующего поколения

Каталог содержит 44 схемы следующего поколения для отдельного инженерного контура `vNext`. Наличие схемы само по себе не означает экспериментально подтверждённую возможность и не изменяет исторические контуры.

Основные правила:

- старые контракты и пакеты выполнения не импортируются и не переписываются;
- истинные метки хранятся отдельно от обнаружения и объяснения;
- `unknown` — состояние знания детектора, а не обязательный истинный класс;
- поколения и группы признаков версионируются независимо;
- правила Sigma не принимаются автоматически;
- восстановление среды выполнения требует автономных архивов OCI и точной проверки идентификаторов;
- канонический JSON использует UTF-8, сортировку ключей, компактные разделители и запрещает NaN.

Машиночитаемый черновик иерархии находится в `behavior_taxonomy_v1.json`. Семантические проверки и вычисление контрольной суммы реализованы в `tools/vnext/contracts.py`.

## Телеметрия и сценарии

Следующий слой добавляет:

- `entity_v1` и `normalized_security_event_v1` для сущностей и типизированных событий;
- `observation_bundle_v1` для причинных окон без статуса инцидента;
- `telemetry_capability_v1` и `behavior_telemetry_requirement_v1` для честной проверки наблюдаемости;
- `scenario_definition_v2`, `scenario_realization_v1`, `execution_unit_vnext_v1` и `ground_truth_v1` для разделения замысла, реализации, запуска, наблюдения и истинной разметки;
- `experimental_dimension_v1` и `generator_capability_v1` для отдельных конструкций поведения и подключаемых генераторов;
- `feature_compatibility_v1` для неизменяемой привязки `network_features_v2`.
- `attack_mapping_v1` для версионированного и привязанного к свидетельствам соответствия базе знаний MITRE без её использования как истинной иерархии.
- `wave1_scenario_registry_v1` для 24 сценариев первой волны, их зрелости, генераторов, возможностей цели и связей со сложными безопасными аналогами.
- `feature_group_v1`, `feature_bundle_v1` и `feature_provider_registry_v1` для независимых групп признаков и явной семантики отсутствующих данных;
- `detector_capability_v1`, `detection_result_v2` и `explanation_bundle_v2` для базового обнаружения с отказом и структурированными свидетельствами;
- `behavior_observability_matrix_v1` и `engineering_fixture_corpus_v1` для машинной карты наблюдаемости и одноразовых технических проверок.
- `context_fact_v1`, `context_profile_v1`, `entity_resolution_v1` и `multi_window_policy_v1` для происхождения контекста, доверия, консервативной личности и временных горизонтов;
- `interaction_graph_v1`, `network_context_feature_group_v1` и `interaction_graph_feature_group_v1` для временных отношений и контекстных признаков;
- `correlation_result_v1`, `incident_candidate_v1` и `attack_chain_hypothesis_v1` для строгого разделения локального решения, многооконной гипотезы и кандидата инцидента;
- `attack_evidence_mapping_v1` и `correlation_registry_v1` для сопоставления ATT&CK по свидетельствам и машинного реестра возможностей.

Реестры рядом со схемами имеют собственные канонические контрольные суммы. Их межконтрактные ограничения проверяют `tools/vnext/telemetry.py` и `tools/vnext/scenarios/registry.py`. Первая волна имеет инженерный статус `implemented`, но не `experimentally_validated`; обратный вызов `DNS`, распределённый подбор и адаптеры старых генераторов остаются `planned`.
