# Платформа «Филин»

> Последний официальный пакет независимой сетевой проверки — `network-validation-execution-8e1e32b127893bdf` с контрольной суммой `8e1e32b127893bdf2e32114b7fb2db19e0e06b2b3de1df5ce2308d2e5571e6cf`. Сам пакет фиксирует 0 научных сессий. Внешний исторический отчёт отдельно сообщает о начале кампании и двух технических попытках, но его операционные записи отсутствуют в репозитории и не подтверждены локально. После выпуска пакета исправлена среда выполнения запуска Zeek; поэтому до выпуска следующего пакета научное выполнение не разрешено.

«Филин» — исследовательская платформа для воспроизводимого анализа сетевых событий. Она связывает контролируемый трафик, извлечение признаков, применение зафиксированного кандидата, пассивную доставку события и лабораторную реконструкцию инцидента. Платформа не является SIEM, не доказывает компрометацию и не выполняет автоматическое блокирование.

## Назначение и задачи

Проект решает четыре связанные задачи:

1. строит причинно упорядоченное 51-признаковое представление сетевого потока;
2. применяет зафиксированный кандидат к эпизоду и публикует только пассивное наблюдение;
3. доставляет наблюдение в локальный приёмник и превращает подтверждающие материалы в наблюдаемые факты;
4. проверяет, насколько такое представление переносится между генераторами, инфраструктурой, целями и сетевыми параметрами.

Основной продуктовый путь заканчивается безопасным пассивным событием. Лабораторная линия поверх него строит реконструкцию, конкурирующие гипотезы и операторскую карточку. Независимая сетевая проверка — отдельная научная процедура и не равна ни лабораторной репетиции, ни подтверждению промышленной готовности.

## Общий поток

```text
контролируемый трафик → PCAP → Zeek → 51 призна́к → зафиксированный кандидат
→ решение эпизода → shadow_event_v2 → локальная доставка
→ подтверждающие материалы → факты → отношения и разрывы
→ конкурирующие гипотезы → карточка v2 → ручное рассмотрение
```

В сетевой процедуре после запуска клиента и цели сохраняется PCAP. Zeek строит `conn.log`, `http.log` и `dns.log`; из временных очищенных журналов извлекается одна строка из 51 числового признака. Сырые PCAP и исходные журналы остаются неизменными. Для модели разрешается только временное исключение строк с маркером; маркер и его метаданные в строку признаков не попадают.

## Независимая сетевая проверка Phase 1

### Матрица

Полная факторная матрица имеет вид:

`6 поведения × 2 семейства генераторов × 2 профиля инфраструктуры × 2 цели × 2 порта × 3 уровня интенсивности = 288 шаблонов`.

Каждый шаблон повторяется три раза, то есть план содержит `288 × 3 = 864` единицы выполнения. Каждому шаблону заранее назначается ровно один режим фоновой активности: `http`, `dns`, `keepalive` или `combined`. Режимы распределены равномерно — по 72 шаблона на каждый вариант — и не образуют дополнительного измерения полного факторного плана. Контрфактуальная часть содержит 24 пары. Подробности и связь с контрактами собраны в [актуальном описании сетевой проверки](docs/research/independent-network-validation.md).

Уровень повторения задаёт разбиение целыми сессиями:

| Повторение | Разбиение |
|---:|---|
| `0` | `development_train` |
| `1` | `development_calibration` |
| `2` | `blind_internal_holdout` |

### Шесть поведений

В матрице используются `navigation` (последовательная навигация), `credential_rejection` (отказы проверки учётных данных), `periodic_callback` (периодический обратный вызов), `throttled_pressure` (ограниченное по скорости давление), `service_discovery` (обнаружение сервисов) и `path_inspection` (исследование путей). Для каждого поведения заранее описаны цель, клиент, сетевой профиль, ожидаемая цель, содержимое PCAP и проверяемые поля Zeek; эти пояснения нельзя заменять только именем идентификатора.

Семейства `family_a` и `family_b`, профили `profile_a` и `profile_b`, реализации целей `target_a` и `target_b` ортогональны. Параметры портов `8080` и `9080` не закреплены за профилем или целью. 24 пары проверяют изменения одного контролируемого фактора и не разрешают выдавать корреляцию за причинность.

### Скрытие информации и журнал

До разблокирования разметки оценщик получает только разрешённую проекцию строки признаков с `evaluation_token`; `primary_split` и `split_assignment` ему запрещены. Сырые PCAP, журналы Zeek, манифесты, идентификатор выполнения `execution_token` и служебные данные сопоставления остаются вне входных данных модели. Запись сопоставления связывает `execution_token` с `evaluation_token`, а эталонная метка хранится отдельно. Сначала фиксируется начало сессии, затем создаётся или проверяется запись сопоставления, и только после этого запускается научное поведение.

Журнал кампании — добавляемый JSONL с порядковым номером и цепочкой SHA-256. Профиль Phase 1 допускает только `session_started`, `session_completed`, `session_failed` и `retry_requested`; внутренние шаги исполнителя не являются событиями журнала. Неуспешная попытка сохраняется. Восстановление допускается только для уже начатой и запечатанной попытки; повторное научное поведение без нового разрешения запрещено. См. [журнал и восстановление](docs/research/phase1-campaign-journal.md) и [ослепление и сопоставление](docs/research/phase1-blinding-and-mapping.md).

### Исторический отчёт и ограничение вывода

Внешний аудит сообщил о начале кампании и двух попытках единицы №1: 0 завершённых научных сессий, единица №2 не запускалась, обе попытки завершились технической ошибкой обработки Zeek с кодом выхода `127`. Операционные записи и PCAP отсутствуют среди отслеживаемых Git-файлов, поэтому это исторически сообщённое, но самостоятельно не подтверждённое состояние. Лимит повторов v4 исчерпан: для него допустимы только аудит без записи, статическая проверка, просмотр артефактов, сверка хешей и контрактов. Оно не заменяет нулевые счётчики снимка состояния внутри официального пакета v4 и не доказывает научный результат.

После выпуска v4 в `phase1_docker_runner.py` исправлены абсолютный путь `/usr/local/zeek/bin/zeek` и вызов `bash -c`; текущая среда выполнения поэтому отличается от зафиксированных контрольных сумм пакета. Исправление не переписывает v4. Сначала должен появиться будущий заменяющий пакет, затем для него создаются новые каталоги результатов и секретов, выполняется новая инициализация кампании с новым журналом нулевого размера, и лишь после этого разрешается предварительная проверка точной единицы №1.

### Приёмка

Критерии приёмки находятся в [контракте критериев](docs/research/phase1-acceptance-criteria.md) и в `lab/network_validation/config/acceptance_criteria.json`: macro-F1 не ниже 0.80, FPR не выше 0.05, полнота каждого класса не ниже 0.65; падение на невидимых семействе, инфраструктуре и цели не более 0.10; реализация параметров не ниже 0.95; контрфактуальные пары не ниже 0.90; обязательна внешняя выборка с macro-F1 не ниже 0.70, FPR не выше 0.10 и полнотой класса не ниже 0.55; доля исключённых строк не выше 0.02; неразрешённые обязательные параметры недопустимы. Ни один критерий ещё не оценивался.

## Модель и 51 признак

Порядок признаков закреплён контрактом `ml/experiments/v0_3_15_4/feature_contract_v2.yaml`; источник вычислений — PCAP и соответствующие журналы Zeek. Разрешены прямое наблюдение, детерминированный вывод, явное отсутствие и неподдерживаемое значение. Нельзя восстанавливать значение по метке, профилю, сценарию или скрытому состоянию генератора. Полное описание всех 51 полей: [контракт признаков Phase 1](docs/research/phase1-feature-construction.md).

## Безопасная установка и проверки

В корне нет единого `requirements.txt` или `pyproject.toml`. Зависимости конкретных подсистем перечислены в их файлах, а для сетевой процедуры — в `lab/network_validation/requirements.lock`. Windows и Fedora/Linux используют разные команды; инструкция не смешивает оболочки: [локальное окружение](docs/getting-started/local-environment.md).

Безопасные проверки:

```powershell
python -m tools.docs.validate_documentation_v2 --strict
python -m tools.docs.validate_documentation_freshness --strict
python -m tools.docs.validate_russian_narrative --strict
python -m tools.docs.validate_documentation_links --strict
python -m tools.docs.validate_documentation_identifiers --strict
python -m tools.docs.validate_documentation_cli --strict
python -m compileall backend collectors incident_reconstruction lab lab_console ml rehearsal staging tools
```

Полный регрессионный запуск может зависеть от локальных пакетов и фиксирует фактическое исходное состояние; требование «абсолютно ноль ошибок» не используется. Текущая политика: `full_regression_passed=false`, `new_regressions_detected=false`, `allowed_baseline_failures=1`, известное изменение `historical_v03155_result_changed`. Список безопасных тестов и интерпретация результатов: [тестирование](docs/getting-started/testing.md).

Команды запуска одной научной единицы, инициализации кампании, раскрытия сопоставления, записи журнала, создания PCAP или обучения модели намеренно не приведены как готовый пример. `run-one-phase1-session` опасна: она создаёт научные данные и требует отдельного явного разрешения.

## Ограничения и лицензии

Используются контролируемые или синтетические среды; внешняя применимость не подтверждена. Гипотеза, путь графа и временное предшествование не являются установленной причиной. Операторские заметки не становятся подтверждающими материалами. Запрещены публичный доступ, промышленная интеграция, реальные уведомления, блокирование и автоматический ответ.
